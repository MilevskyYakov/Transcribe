# Экранная карта Mnema

## Назначение

Этот документ — единый UX-каркас установленного macOS-приложения Mnema до выбора визуального направления и реализации. Канонический путь:

`добавить запись → настроить → обработать → открыть готовый Markdown`.

Mnema — рабочий инструмент транскрибации, не редактор. В каждый момент центральная область решает одну задачу и показывает одно первичное действие. Обработка продолжается в фоне при переходе к другой задаче.

## Общий каркас

```text
┌──────────────────────┬──────────────────────────────────────────────────────┐
│ MNEMA                │ Заголовок текущего состояния                         │
│                      │ Короткое пояснение                                   │
│ + Новая транскрипция ├──────────────────────────────────────────────────────┤
│   Поиск              │                                                      │
│                      │ Одна рабочая область                                 │
│ История              │                                                      │
│   задача / пакет     │ Основной объект → состояние → одно primary action    │
│   задача             │                                                      │
│                      │ Вторичные действия рядом с объектом или в «Ещё»      │
│ ⚙ Настройки          │                                                      │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

Левая панель постоянна:

- `Новая транскрипция` всегда открывает чистое состояние добавления, не останавливая фоновые задачи;
- `Поиск` фильтрует историю по названию файла или транскрипции;
- история показывает последние задачи, а пакет — одной раскрываемой группой;
- `Настройки` находятся внизу;
- короткий индикатор фоновой активности допустим у элемента истории, но технические статусы backend, моделей, API и updater здесь не показываются.

Рабочая область заменяется целиком при переходе между добавлением, настройкой, обработкой, результатом, историей и настройками. Форма новой записи не остаётся над открытой задачей.

## Сводка состояний

| Состояние | Цель | Primary action | Secondary actions |
|---|---|---|---|
| Запуск | Начать новую транскрипцию | `Выбрать файлы` | открыть историю, настройки |
| Drag-over | Подтвердить место добавления | отпустить файлы | — |
| Один файл выбран | Проверить назначение задачи | `Начать транскрибацию` | `Изменить` папку, заменить/убрать файл |
| Папка не настроена | Выбрать назначение результата | `Выбрать папку` | открыть настройки |
| Несколько файлов | Настроить текущий файл пакета | `Начать транскрибацию` | изменить общую/личную папку, убрать файл |
| Обработка | Понять, что происходит | `Новая транскрипция` | открыть другую задачу, `Ещё` |
| Ошибка задачи | Возобновить конкретную задачу | `Повторить` | показать детали, открыть папку задачи |
| Результат | Забрать готовый файл | `Открыть Markdown` | `Показать в Finder`, `Новая транскрипция`, `Ещё` |
| Low-confidence diarization | Забрать честный результат без ложных подписей | `Открыть Markdown` | `Показать в Finder`, `Ещё` |
| История | Найти прежний результат | открыть выбранную задачу | поиск, раскрыть пакет |
| Настройки | Изменить постоянные значения | `Готово` | управление моделями, updater, диагностика |
| Backend problem | Вернуть Mnema в рабочее состояние | `Повторить запуск` | открыть диагностику |
| Model problem | Подготовить модель | `Открыть настройки моделей` | выбрать другую готовую модель |

## 1. Запуск и добавление файлов

### Цель

Добавить одну или несколько записей. При каждом запуске app открывается это состояние, а не последняя задача.

### Видимый текст

- Заголовок: `Новая транскрипция`
- Подзаголовок: `Добавьте аудио или видео`
- Drop-сообщение: `Перетащите записи сюда`
- Подсказка: `Можно добавить один или несколько файлов`
- Кнопка: `Выбрать файлы`

### Расположение

```text
┌─────────────────────────────────────────────────────────────┐
│ Новая транскрипция                                          │
│ Добавьте аудио или видео                                    │
│                                                             │
│        [выразительный visual добавления / сигнала]          │
│                                                             │
│              Перетащите записи сюда                         │
│           Можно добавить один или несколько                 │
│                    [Выбрать файлы]                           │
└─────────────────────────────────────────────────────────────┘
```

Вся центральная рабочая область является native Tauri drop target. `Выбрать файлы` остаётся компактной альтернативой и открывает multi-select системного диалога.

### Primary action

`Выбрать файлы`; при drag-and-drop его эквивалент — отпустить файлы.

### Переходы

- один поддерживаемый файл → `Один файл выбран`;
- несколько поддерживаемых файлов → `Пакетная сессия`;
- неподдерживаемый объект → состояние остаётся прежним, рядом с drop-area: `Этот тип файла не поддерживается. Выберите аудио или видео.`;
- история / настройки открываются из левой панели.

### Drag-over

Вся рабочая область получает заметную границу/подсветку; visual реагирует на ввод. Текст меняется на `Отпустите файлы здесь`. Остальные элементы приглушаются, новых действий не появляется.

## 2. Один файл выбран

### Цель

Проверить файл и папку результата, затем запустить обработку.

### Видимый текст и блоки

- Заголовок: `Новая транскрипция`
- Карточка файла: имя, тип/размер при наличии, действие замены или удаления;
- `Сохранить в: <имя папки>`;
- рядом текстовая кнопка `Изменить`;
- primary: `Начать транскрибацию`.

Поля `Участники` нет. Отдельного обязательного поля названия нет: отображаемое имя берётся из файла; переименование результата не входит в этот экранный контракт.

```text
┌─────────────────────────────────────────────────────────────┐
│ Новая транскрипция                                          │
│                                                             │
│ [visual]  Созвон с клиентом.m4a                    [Убрать] │
│           Сохранить в: Встречи                  [Изменить] │
│                                                             │
│                                    [Начать транскрибацию]    │
└─────────────────────────────────────────────────────────────┘
```

### Primary action

`Начать транскрибацию`.

### Переходы

- запуск → `Обработка` выбранной задачи;
- новый drop / системный выбор → заменяет файл или превращает выбор в пакет;
- `Изменить` → системный выбор папки только для этой задачи; глобальная папка не меняется;
- `Убрать` → `Запуск и добавление файлов`.

## 3. Папка не настроена

Это блокирующий вариант настройки одного файла или текущего файла пакета, а не отдельная глобальная ошибка.

- Текст: `Выберите папку, куда Mnema сохранит готовый Markdown.`
- Primary: `Выбрать папку`.
- Secondary: `Открыть настройки`.
- После выбора пользователь возвращается в ту же форму; запуск не происходит автоматически.

Папка задачи наследуется из настроек только как начальное значение. Изменение папки задачи не меняет настройку по умолчанию.

## 4. Пакетная сессия

Несколько файлов создают одну сессию, но каждый файл остаётся отдельной canonical job.

### Цель

Настроить и сразу запустить текущий файл, не дожидаясь настройки остальных.

### Расположение

```text
┌─────────────────────────────────────────┬───────────────────┐
│ Пакет · 2 из 4                          │ Очередь           │
│                                         │ ✓ 01.m4a Готово   │
│ [та же карточка файла, что в single]    │ • 02.mov Настроить│
│ 02.mov                                  │   03.wav Настроить│
│ Общая папка: Встречи        [Изменить] │   04.mp3 Настроить│
│ Сохранить в: Встречи         [Иначе…]  │                   │
│                                         │                   │
│                 [Начать транскрибацию]  │                   │
└─────────────────────────────────────────┴───────────────────┘
```

Статусы файла: `Настроить`, `Обрабатывается`, `Готово`, `Ошибка`. Текущий настраиваемый файл использует ту же базовую форму и copy, что single-file сценарий.

### Primary action

`Начать транскрибацию` для текущего файла.

### Переходы

- после запуска текущий файл получает `Обрабатывается`, а форма сразу переходит к следующему `Настроить`;
- выбор файла в очереди открывает его форму;
- изменение общей папки применяется к ещё не переопределённым файлам;
- `Иначе…` задаёт папку только текущему файлу;
- после настройки последнего файла рабочая область показывает общую очередь;
- ошибки не останавливают остальные файлы;
- завершение всей сессии → пакетный итог; primary `Открыть результаты` открывает раскрытую группу результатов;
- `Повторить` доступно только у ошибочного файла и не перезапускает остальные.

## 5. Обработка

### Цель

Понять текущий этап и оставить задачу работать в фоне.

### Видимый текст и блоки

- имя записи;
- человекочитаемый этап, например `Распознаём речь`;
- прогресс, если backend умеет его достоверно сообщить;
- `Можно закрыть эту задачу — обработка продолжится в фоне`;
- краткая хронология завершённых этапов без raw event log.

```text
┌─────────────────────────────────────────────────────────────┐
│ Созвон с клиентом                         Обрабатывается     │
│                                                             │
│              [выразительный visual сигнала]                 │
│                    Распознаём речь                           │
│                    ███████░░ 68%                             │
│                                                             │
│ Обработка продолжится в фоне                                │
└─────────────────────────────────────────────────────────────┘
```

### Primary action

`Новая транскрипция` в левой панели. В рабочей области нет конкурирующего CTA: состояние само обновляется.

### Secondary actions и переходы

- выбрать другую задачу или пакет в истории;
- `Ещё` → журнал/промежуточные артефакты, если они нужны для поддержки;
- успех → `Результат`;
- failure → `Ошибка задачи`;
- при переходе в фон у задачи остаётся живой статус в истории.

## 6. Ошибка задачи

### Цель

Понять полезную причину и повторить только сломанную задачу.

- Заголовок: `<имя файла>`
- Статус: `Не удалось обработать`
- Сообщение переводит известную техническую причину в действие пользователя; raw error скрыт в `Технические детали`.
- Primary: `Повторить`.
- Secondary: `Технические детали`, `Показать папку задачи`, `Новая транскрипция`.

В пакетной сессии ошибка отображается на строке конкретного файла; остальные продолжают работу. Повтор сохраняет настройки и папку этого файла.

## 7. Результат

### Цель

Открыть готовый Markdown. Это не встроенный редактор и не dashboard пайплайна.

### Видимый текст и блоки

- имя записи;
- статус `Готово` или `Готово с предупреждением`;
- имя и папка сохранённого Markdown;
- короткий read-only preview результата допустим для уверенности, но не получает edit controls;
- `Ещё` содержит промежуточные артефакты, журнал и диагностику.

```text
┌─────────────────────────────────────────────────────────────┐
│ Стратегическая встреча                                Готово│
│ Стратегическая встреча.md · Встречи                         │
│                                                             │
│ [Открыть Markdown]   Показать в Finder   Новая транскрипция │
│                                                             │
│ Короткий read-only preview                                  │
│                                                   [Ещё ▾]   │
└─────────────────────────────────────────────────────────────┘
```

### Primary action

`Открыть Markdown`.

### Secondary actions и переходы

- `Показать в Finder`;
- `Новая транскрипция` → чистый старт;
- `Ещё` → промежуточные артефакты, журнал, диагностика;
- если внешний Markdown отсутствует: статус `Файл не найден`, primary `Сохранить заново`, secondary `Изменить папку`.

На результате декоративный visual почти исчезает: остаётся только небольшой знак завершения. Главные объекты — файл и действия.

## 8. Low-confidence diarization

Это вариант результата, а не шаг ручного исправления.

- Статус: `Готово с предупреждением`;
- Сообщение: `Голоса не удалось разделить достаточно надёжно. Текст сохранён в хронологическом порядке без подписей.`;
- preview и Markdown содержат последовательный текст/таймлайн без ложных имён и `Спикер 1/2`;
- нет формы назначения имён и предложения угадать участников;
- primary: `Открыть Markdown`;
- технические метрики уверенности доступны только в `Ещё → Диагностика`.

Если разделение голосов надёжно, отображаются подтверждённые пользовательские подписи или нейтральные labels согласно будущему speaker contract. Экранная карта не задаёт алгоритм порога.

## 9. История и поиск

### Цель

Найти и открыть прежнюю задачу или пакет.

Левая панель показывает компактный список. Полный режим истории открывается через `Поиск` или заголовок секции:

- поле `Поиск по записям`;
- группы по дате;
- строка задачи: название, статус, дата;
- строка пакета: название/дата, `N файлов`, агрегированный статус; раскрытие показывает canonical jobs;
- primary — открыть выбранную задачу;
- выбор готовой задачи → `Результат`, активной → `Обработка`, ошибочной → `Ошибка задачи`, пакета → его очередь/итог.

Поиск и фильтрация не являются отдельной пользовательской сущностью и не требуют нового backend pipeline.

## 10. Настройки

### Цель

Изменить постоянные настройки, которые не должны конкурировать с рабочим сценарием.

Разделы:

1. `Сохранение` — папка по умолчанию;
2. `Распознавание` — модель по умолчанию и управление скачанными моделями;
3. `Обновления` — версия и updater;
4. `Диагностика` — backend lifecycle, media tools, local API, data/cache paths, обслуживание и raw logs;
5. `Автоматизация` — batch-by-path/watch-folder только как supporting developer/automation surface, не как пользовательский пакетный flow.

Primary: `Готово` — сохранить изменения и вернуться к предыдущему рабочему состоянию. Выбор системной папки/модели может сохраняться сразу, но визуально остаётся частью одного settings flow.

## 11. Backend и model problems

### Backend problem

Если локальный backend не запустился, рабочая область заменяется полезным error-state:

- `Mnema не удалось запустить обработку`;
- краткая безопасная причина, если она известна;
- primary `Повторить запуск`;
- secondary `Открыть диагностику`.

API URL, stack trace и recent output не показываются до открытия диагностики.

### Model problem

Если для запуска нет готовой модели, выбранный файл и его настройки сохраняются:

- `Модель распознавания не готова`;
- состояние скачивания или понятная причина ошибки;
- primary `Открыть настройки моделей`;
- secondary — выбрать другую уже готовую модель, если она есть.

После подготовки модели пользователь возвращается в форму; задача не стартует автоматически.

## Visual placement contract

- Добавление: самый заметный decorative visual; он объясняет drop target и реагирует на drag-over.
- Настройка single/batch: visual уменьшается и не конкурирует с именем файла, папкой и запуском.
- Обработка: второй заметный visual, связанный с живым сигналом/ходом работы.
- Результат: visual почти исчезает; файл и actions важнее.
- История, настройки и диагностика: декоративных visual нет.
- Экранная карта не выбирает метафору, палитру, шрифт, логотип или иконку.

## Переходы

```text
Запуск
  ├─ 1 файл ─→ Настройка файла ─→ Обработка ─┬─→ Результат
  │                     └─ нет папки         └─→ Ошибка ─→ Повтор
  └─ N файлов → Пакет / текущий файл ─→ следующий файл
                       └─ очередь ─→ пакетный итог

История ─→ Настройка активной / Обработка / Ошибка / Результат
Настройки ─→ предыдущее рабочее состояние
Backend/model problem ─→ исправление ─→ сохранённое рабочее состояние
```

## Требования к следующим implementation Issues

Экранная карта не проектирует API, но реализация потребует проверить или добавить совместимый контракт для:

- native Tauri multi-file drag-and-drop и системного multi-select;
- per-job output folder с наследованием default и без изменения global setting;
- batch session id/grouping поверх отдельных canonical jobs, последовательной настройки и retry одного файла;
- агрегированного статуса пакета для истории и финального уведомления;
- безопасных действий `Открыть Markdown` и `Показать в Finder`;
- явного degraded diarization signal, достаточного, чтобы UI и exporter не показывали ложные подписи;
- фонового lifecycle задачи независимо от выбранного экрана.

Нельзя переносить filesystem orchestration или speech pipeline в React/Tauri UI. Browser dashboard сохраняет совместимость с local API, но не определяет продуктовый UX.

## Прежний UI, который больше не является целевым

Исторические задачи остаются evidence реализованных возможностей, но следующие решения заменены:

- #19: drop target больше не ограничен старой upload-zone; канон — native Tauri drop на всей центральной рабочей области, multi-file создаёт пакет;
- #21: папка больше не только глобальная autosave-настройка после обработки; default наследуется каждой задачей и может быть переопределён до запуска;
- #23: обязательный `Проверьте спикеров` и participant hints не являются общим flow; имена допустимы только после надёжного разделения, low-confidence сохраняется без ложных подписей;
- #25: upload, processing, transcript, diagnostics и artifacts больше не складываются в один длинный экран; центральная область показывает одно состояние за раз;
- текущие `Backend`, `Media tools`, модель, updater, API, batch-by-path, watch-folder и cleanup уходят с главной поверхности в настройки;
- текущая форма `Название транскрибации` + `Участники` не является целевой базовой формой;
- текущий result-grid с постоянно раскрытыми `Процесс`, `Проверки`, `Сохранение Markdown` и `Артефакты` заменяется файлом результата, тремя действиями с одной primary hierarchy и свёрнутым `Ещё`.

## Проверка покрытия parent #51

Документ фиксирует все принятые решения parent, относящиеся к экранному контракту:

- запуск с новой транскрипции;
- левая панель: новая, поиск, история, настройки;
- одно главное состояние за раз и фоновая обработка;
- whole-workspace drop + `Выбрать файлы`;
- per-job folder с default inheritance;
- отсутствие поля участников;
- единая single/batch форма, последовательная настройка и независимый retry;
- пакет как группа истории при отдельных canonical jobs;
- отсутствие встроенного редактора;
- честный хронологический low-confidence result;
- result actions и скрытые technical artifacts;
- размещение visual только в добавлении/обработке;
- technical panels в настройках;
- app-first Tauri boundary без новых публичных/cloud surfaces.
